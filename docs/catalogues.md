# Catalogues

A catalogue set annotates fields of one kind of meaning, for every rule APB2 packages; `data/catalogues.json` states each set's purpose and users, and `Catalog.description` and `DataCatalog.description` return it. The JSON files under `src/apb_catalog/data/sources/<set>/`, one per vendor, `src/apb_catalog/data/producers/<set>/`, one per APB producer, and `src/apb_catalog/data/annotations/<set>/`, one per sample-annotation convention, are the source of truth. `apb-catalog table` writes them all as one long table. `make docs-tables` generates each set's kinds, coverage and entry tables below from them; the prose is written by hand.

## `chromatography`

Observed retention times retained by APB2, with their original unit. DIA-NN and MaxQuant report minutes; AlphaDIA reports seconds. FragPipe documents instrument-dependent units, and AlphaPept's unit is not established for every supported input route, so those entries record `unit="unknown"`. The catalogue returns values unchanged; a consumer must resolve the unit before converting to QPX seconds. MaxQuant's modification-specific peptide RT is a feature annotation averaged over evidence, distinct from its per-run evidence RT layer.

<!-- generated by scripts/coverage_tables.py: chromatography -->

Kinds:

- `retention_time`: Observed retention time of the identified feature, rather than predicted RT or library iRT.

Original time units, the `unit` qualifier every entry declares:

- `second`: Seconds; multiply by 1 to express the value in QPX seconds.
- `minute`: Minutes; multiply by 60 to express the value in QPX seconds.

Coverage by software version, one table per level. A cell names the APB column that answers, with the vendor columns APB2 computes it from (`apb_Decoy` ← `Decoy`); ✗ means nothing is catalogued. Units describe the original values; `unknown` units must be resolved before converting to seconds. Per-run RT layers and a feature's experiment-wide RT annotation are different locations.

## `confidence`

How likely each identification, or the signal quantified for it, is correct; used by apb-aggregate for confidence-weighted rollups and by apb-export's prolfqua target: per-run PEP and q-value layers, per-feature PEP, Sage's MS1-peak q-value (stage `quantification`), and DIA-NN's, Spectronaut's and MaxQuant's protein-group q-values. Scores, vendor summaries and other vendors' protein-level confidence are deliberately left out.

<!-- generated by scripts/coverage_tables.py: confidence -->

Kinds:

- `pep`: Posterior error probability: the probability that this single identification is wrong; lower is better.
- `q_value`: The smallest false discovery rate at which this identification, or quantified signal, is accepted; lower is better.
- `library_q_value`: The q-value of the identification's spectral-library entry, built across all runs; lower is better.
- `global_q_value`: The q-value of the identification across the whole experiment; lower is better.

Coverage by software version, one table per level. A cell names the APB column that answers, with the vendor columns APB2 computes it from (`apb_Decoy` ← `Decoy`); ✗ means nothing is catalogued. Per run is a layer, one value per sample; per feature is a var column, one value across the experiment.

## `abundance`

What each abundance layer measures, and whether the software normalizes it across runs; used by apb-proteobench modules that ask for an un-normalized layer, such as `dia_plasma`. Unlike the consumer sets above, it describes every layer an APB2 rule marks with the role `abundance`, and a test keeps its entries equal to those layers.

- `normalization` is static per column: `none` when the software never normalizes it, `run_setting` when the run's settings decide. Which method a run used, such as DIA-NN's RT-dependent or global normalization, directLFQ or TIC, is not catalogued
- `unknown` marks what the evidence does not establish: the normalization of FragPipe's, MetaMorpheus's, quantms's, i2MassChroQ's, Sage's and pb_custom's intensities and of Spectronaut's `EG.*Quantity (Settings)`; the kind of Spectronaut's `PG.Quantity`, which the run's protein quantity method decides, and of `PG.MaxLFQ` under DIA-NN's 1.8–1.9 and 2 rules, which QuantUMS or legacy MaxLFQ computes depending on the quantification strategy; and of MSAngel's protein-set `Abundance` and `Raw_Abundance`, which Proline sums or fits as the run's quantitation settings choose, which the workbook does not state
- A lookup on a level with an `unknown` entry raises `UnresolvedField` whose `resolution.status` is `unknown`; entries sharing kind and normalization, such as AlphaPept's four un-normalized MS1 measures, make it `ambiguous`
- Left out: DIA-NN's `Genes.MaxLFQ`, a gene-group quantity on the protein-group level

<!-- generated by scripts/coverage_tables.py: abundance -->

Kinds and where they are required:

- `intensity`, SHOULD with normalization `none` on peptidoform_ion: A measured signal of the level's feature, summed, integrated or at apex, at the MS level the software quantifies on.
- `ms1_intensity`: A measured MS1 signal, reported beside the software's fragment-based quantity.
- `maxlfq`: A MaxLFQ estimate: delayed normalization and maximal peptide-ratio extraction (Cox et al. 2014).
- `ibaq`: Intensity-based absolute quantification: summed intensity divided by the number of theoretically observable peptides.
- `directlfq`: A directLFQ estimate (Ammar et al. 2023).

Normalization, the `normalization` qualifier every entry declares:

- `none`: The software never normalizes this column.
- `run_setting`: The column carries whatever cross-run normalization the run's settings chose, possibly none.

Coverage by software version, one table per level. A cell names the APB column that answers, with the vendor columns APB2 computes it from (`apb_Decoy` ← `Decoy`); ✗ means nothing is catalogued. A column pairs a kind with its normalization; `unknown` marks what the evidence does not establish.

## `apb`

The fields APB writes for every vendor, asked for by kind instead of by name: the ProForma identifiers, the decoy and contaminant flags, the var columns a rule's roles name, and a sample annotation's condition and biological replicate. Used by apb-export's export rules, so no rule names an APB column. Its requirements state which levels carry each fixed column; `peptidoform` is only SHOULD on the peptidoform level because MaxQuant's peptidoform level has no positions, and `peptidoform_fragment` only SHOULD because Spectronaut keys fragments on its own columns.

<!-- generated by scripts/coverage_tables.py: apb -->

Kinds and where they are required:

- `peptide`, MUST on peptidoform_ion, peptidoform, peptide and peptidoform_fragment: The plain amino-acid sequence: ProForma_peptide (PSI-MS MS:1000888, stripped peptide sequence).
- `peptidoform`, MUST on peptidoform_ion and peptidoform_fragment; SHOULD on peptidoform: The sequence with its modifications in ProForma notation: ProForma_peptidoform (PSI-MS MS:1003169, proforma peptidoform sequence).
- `peptidoform_unlocalized`, MAY on peptidoform: The sequence with modifications whose positions the vendor does not report, as ProForma unknown-position groups: ProForma_peptidoform_unlocalized, which MaxQuant's peptidoform level writes instead of ProForma_peptidoform.
- `peptidoform_ion`, MUST on peptidoform_ion and peptidoform_fragment: The peptidoform with its charge: ProForma_ion (PSI-MS MS:1003270, proforma peptidoform ion notation).
- `peptidoform_fragment`, SHOULD on peptidoform_fragment: A fragment of a peptidoform ion: ProForma_ion with the fragment label, ProForma_fragment.
- `decoy`, MUST on peptidoform_fragment, peptidoform_ion, peptidoform, peptide and protein: Whether the vendor marks the feature as a decoy: apb_Decoy.
- `contaminant`, MUST on peptidoform_fragment, peptidoform_ion, peptidoform, peptide and protein: Whether the vendor marks the feature as a contaminant it flags or adds itself: apb_Contaminant.
- `protein_assignment`, SHOULD on peptidoform_fragment, peptidoform_ion, peptidoform and peptide: The protein or protein group the vendor assigns the feature to: the var column the level's rule marks with the role protein_assignment.
- `fasta_accessions`, MAY on peptidoform_fragment, peptidoform_ion, peptidoform, peptide and protein: The FASTA accessions the vendor lists for the feature: the var column the level's rule marks with the role fasta_accessions.
- `condition`: The experimental group a sample belongs to, as MSstats' Condition.
- `bioreplicate`: The biological replicate a sample comes from; one value across conditions marks a repeated subject, as MSstats' BioReplicate.

APB writes these fields itself, so they need no vendor review: the fixed columns keep their names for every vendor, a role names the var column the level's rule marks, and a prefix finds a sample-annotation column of the convention the result records. `apb-catalog check apb` checks every packaged rule level against the requirements.

## Reporting standards

- The released reporting guideline for quantitative proteomics results is [MIAPE-Quant 1.0](https://github.com/HUPO-PSI/MIAPE/blob/main/MIAPE_Quant_v1.0_Final_0.pdf) (HUPO-PSI, 2012)
- It asks, among other items, for quantification values per feature, identified by peptide sequence or by sequence plus charge state; APB's peptidoform-ion level holds that feature
