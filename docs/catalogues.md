# Catalogues

A catalogue set annotates fields of one kind of meaning, for every rule APB2 packages; `data/catalogues.json` states each set's purpose and users, and `Catalog.description` returns it. The JSON files under `src/apb_catalog/data/sources/<set>/`, one per vendor, and `src/apb_catalog/data/producers/<set>/`, one per APB producer, are the source of truth. `make docs-tables` generates each set's kinds, coverage and entry tables below from them; the prose is written by hand.

## `identification_confidence`

How likely each identification, or the signal quantified for it, is correct; used by apb-aggregate for confidence-weighted rollups and by apb-export's prolfqua target: per-run PEP and q-value layers, per-feature PEP, Sage's MS1-peak q-value (stage `quantification`), and DIA-NN's, Spectronaut's and MaxQuant's protein-group q-values. Scores, vendor summaries and other vendors' protein-level confidence are deliberately left out.

<!-- generated by scripts/coverage_tables.py: identification_confidence -->

Concept `confidence`, kinds:

- `pep`: Posterior error probability: the probability that this single identification is wrong; lower is better.
- `q_value`: The smallest false discovery rate at which this identification, or quantified signal, is accepted; lower is better.
- `library_q_value`: The q-value of the identification's spectral-library entry, built across all runs; lower is better.
- `global_q_value`: The q-value of the identification across the whole experiment; lower is better.

Coverage by software version, one table per level. A cell names the APB column that answers, with the vendor columns APB2 computes it from (`apb_Decoy` ← `Decoy`); ✗ means nothing is catalogued. Per run is a layer, one value per sample; per feature is a var column, one value across the experiment.

## `abundance`

What each abundance layer measures, and whether the software normalizes it across runs; used by apb-proteobench modules that ask for an un-normalized layer, such as `dia_plasma`. Unlike the consumer sets above, it describes every layer an APB2 rule marks with the role `abundance`, and a test keeps its entries equal to those layers.

- `normalization` is static per column: `none` when the software never normalizes it, `run_setting` when the run's settings decide. Which method a run used, such as DIA-NN's RT-dependent or global normalization, directLFQ or TIC, is not catalogued
- `unknown` marks what the evidence does not establish: the normalization of FragPipe's, MetaMorpheus's, quantms's, i2MassChroQ's, Sage's and pb_custom's intensities and of Spectronaut's `EG.*Quantity (Settings)`; the kind of Spectronaut's `PG.Quantity`, which the run's protein quantity method decides, and of `PG.MaxLFQ` under DIA-NN's 1.8–1.9 and 2 rules, which QuantUMS or legacy MaxLFQ computes depending on the quantification strategy
- A lookup on a level with an `unknown` entry raises `UnresolvedField` whose `resolution.status` is `unknown`; entries sharing kind and normalization, such as AlphaPept's four un-normalized MS1 measures, make it `ambiguous`
- Left out: DIA-NN's `Genes.MaxLFQ`, a gene-group quantity on the protein-group level

<!-- generated by scripts/coverage_tables.py: abundance -->

Concept `abundance`, kinds:

- `intensity`: A measured signal of the level's feature, summed, integrated or at apex, at the MS level the software quantifies on.
- `ms1_intensity`: A measured MS1 signal, reported beside the software's fragment-based quantity.
- `maxlfq`: A MaxLFQ estimate: delayed normalization and maximal peptide-ratio extraction (Cox et al. 2014).
- `ibaq`: Intensity-based absolute quantification: summed intensity divided by the number of theoretically observable peptides.
- `directlfq`: A directLFQ estimate (Ammar et al. 2023).

Normalization, the `normalization` qualifier every entry declares:

- `none`: The software never normalizes this column.
- `run_setting`: The column carries whatever cross-run normalization the run's settings chose, possibly none.

Coverage by software version, one table per level. A cell names the APB column that answers, with the vendor columns APB2 computes it from (`apb_Decoy` ← `Decoy`); ✗ means nothing is catalogued. A column pairs a kind with its normalization; `unknown` marks what the evidence does not establish.
